ການຕັ້ງຄ່າ Network & Static IP

ສິ່ງທຳອິດທີ່ຕ້ອງເຮັດກ່ອນ Config ລະບົບ Windows Server ໃນ VMware Workstation.

🗣️ປະເດັນສຳຄັນໃນການອະທິບາຍ

1. ເປັນຫຍັງຕ້ອງໃຊ້ Static IP?

ເພາະເຊີເວີນີ້ຈະເປັນ Domain Controller ແລະ DNS Server. ຖ້າໃຊ້ IP ແບບ DHCP (ປ່ຽນແປງພາຍຫຼັງ), client ຈະຊອກຫາ AD ບໍ່ເຫັນ ແລະ ລະບົບຈະລົ້ມທັນທີ.

2. ຕັ້ງຄ່າ VMware NAT Mode

ໃນ VMware, Network Adapter ຕ້ອງເປັນ NAT Mode ເພື່ອໃຫ້ Virtual Machine ແບ່ງປັນ Internet ກັບ Host ໄດ້ສະດວກ.

3. Preferred DNS Server

ຕ້ອງກຳນົດເປັນ 127.0.0.1 (Loopback address) ເພາະເຊີເວີນີ້ເປັນຕົວບໍລິການ DNS ໃຫ້ກັບ Active Directory ໃນຕົວເອງ.

❓ ຄຳຖາມຖາມນັກຮຽນ: "ຖ້າເຮົາບໍ່ຕັ້ງ DNS ໄປຫາຕົວເອງ (127.0.0.1) ແຕ່ໃສ່ 8.8.8.8 ແທນ, client ຈະ join domain ໄດ້ບໍ່?" (ຄຳຕອບ: ບໍ່ໄດ້, ເພາະ DNS 8.8.8.8 ຂອງ Google ບໍ່ຮູ້ຈັກຊື່ Domain local ຂອງເຮົາ)

ການອອກແບບໂຄງສ້າງອົງກອນ (Active Directory Hierarchy)

ອອກແບບໂຄງສ້າງ OU ເພື່ອຮອງຮັບພະນັກງານ ແລະ ຄຸ້ມຄອງລະບົບຢ່າງເປັນລະບຽບ.

🗣️ປະເດັນສຳຄັນໃນການອະທິບາຍ

1. Domain: Root ສູງສຸດ

ເປັນຈຸດເລີ່ມຕົ້ນຂອງທຸກຢ່າງ ປຽບເໝືອນຊື່ຂອງບໍລິສັດ ເຊັ່ນ ChaleunIT.local.

2. Main OU: ແຍກສ່ວນຈັດການ

ສ້າງ OU ຫຼັກຊື່ Chaleun_Staff ເພື່ອຈັດເກັບພະນັກງານ ແລະ ແຍກອອກຈາກ System Objects ເກົ່າຂອງ Windows.

3. Sub-OU (Departments)

ແບ່ງ OU ຍ່ອຍຕາມຜະແໜກ (IT, HR, Sales) ເພື່ອສະດວກໃນການຜູກ Group Policy ທີ່ແຕກຕ່າງກັນ.

💡 ເຄັດລັບການສອນ: ອະທິບາຍໃຫ້ນັກຮຽນເຫັນພາບວ່າ OU ປຽບເໝືອນ "ລິ້ນຊັກ" ທີ່ໃຊ້ຈັດລະບຽບເອກະສານ ຫາກບໍ່ມີ OU ຈະບໍ່ສາມາດຜູກ GPO ໃສ່ກຸ່ມພະນັກງານສະເພາະໄດ້.

ບົດທີ 2

ການບໍລິຫານຈັດການ Group Policy Objects (GPO)

ການບັງຄັບໃຊ້ກົດລະບຽບຄວາມປອດໄພ ແລະ ການຈັດການ Wallpaper ຈາກຈຸດສູນກາງ.

🗣️ປະເດັນສຳຄັນໃນການອະທິບາຍ

1. GPO Link: ສ້າງແລ້ວຕ້ອງຜູກ

ສ້າງກົດ (GPO) ແລ້ວ ຕ້ອງນຳໄປ Link ໃສ່ OU ທີ່ຕ້ອງການ, ຫາກບໍ່ Link ຈະບໍ່ມີຜົນບັງຄັບໃຊ້.

2. User vs Computer Policy

ແຍກໃຫ້ອອກລະຫວ່າງກົດທີ່ບັງຄັບຕາມ User (ເຊັ່ນ: ຫ້າມເປີດ Control Panel) ກັບ Computer (ເຊັ່ນ: ປິດ Windows Update).

3. gpupdate /force (ຄຳສັ່ງຫຼັກ)

ປົກກະຕິເຄື່ອງ client ຈະອັບເດດກົດທຸກໆ 90 ນາທີ. ເພື່ອໃຫ້ກົດມີຜົນທັນທີ ໃຫ້ເປີດ CMD ແລ້ວພິມ:

gpupdate /force

ບົດທີ 3

ການບໍລິຫານຈັດການສິດທິໃນການເຂົ້າເຖິງ (Share vs NTFS Permissions)

ຄວາມແຕກຕ່າງລະຫວ່າງປະຕູຮົ້ວເຄືອຂ່າຍ ແລະ ປະຕູຫ້ອງໄຟລ໌ລະບົບ.

🗣️ປະເດັນສຳຄັນໃນການອະທິບາຍ

1. Share Permission (ປະຕູຊັ້ນນອກ)

ປຽບເໝືອນ "ປະຕູຮົ້ວໜ້າບ້ານ". ໃຊ້ຄຸມການເຂົ້າເຖິງຜ່ານເຄືອຂ່າຍ. ແນະນຳໃຫ້ Add ສະເພາະກຸ່ມທີ່ຕ້ອງການ ແລະ Remove 'Everyone' ອອກ.

2. NTFS Permission (ປະຕູຊັ້ນໃນ)

ປຽບເໝືອນ "ປະຕູຫ້ອງນອນ" (Security tab). ຄຸມລະອຽດລະດັບໄຟລ໌/ໂຟນເດີ ບໍ່ວ່າຈະເຂົ້າທາງເຄືອຂ່າຍ ຫຼື ຫຼິ້ນຢູ່ໜ້າເຄື່ອງເຊີເວີ.

3. Most Restrictive Wins!

ເມື່ອສິດທິທັງສອງຂັດກັນ, ສິດທິທີ່ເຄັ່ງຄັດທີ່ສຸດ (Restricted ທີ່ສຸດ) ຈະຖືກບັງຄັບໃຊ້ສະເໝີ ເຊັ່ນ: Share ເປັນ Read ແຕ່ NTFS ເປັນ Modify = ຜົນລັບຈະເປັນໄດ້ພຽງ Read.

ການເພີ່ມປະສິດທິພາບ File Server (FSRM Tools)

ການຄວບຄຸມການນຳໃຊ້ພື້ນທີ່ ແລະ ຄວາມປອດໄພລະດັບ File Server.

🚀

🗣️ ປະເດັນສຳຄັນໃນການອະທິບາຍ: FSRM (File Server Resource Manager)

ໃຊ້ປ້ອງກັນບໍ່ໃຫ້ Disk ເຕັມໄວຈາກໄຟລ໌ເພງ/ໜັງ, ຊ່ອນໂຟນເດີທີ່ບໍ່ມີສິດເຫັນເພື່ອຄວາມປອດໄພ ແລະ ຕັ້ງຄ່າກູ້ຄືນໄຟລ໌ເມື່ອຖືກລຶບ.

📊1. ຈຳກັດພື້ນທີ່ (Quota Management)

ໂຈດ: ບັງຄັບ Quota ໃນໂຟນເດີ IT_Data ຫ້າມເກີນ 100 MB (Hard Quota).

ພື້ນທີ່ທີ່ໃຊ້ (Used Space) 70 MB / 100 MB (70%)
❌ Error: Disk quota exceeded on 'IT_Data'. Hard Quota active — ໄຟລ໌ຖືກ Block ທັນທີ!

⛔2. ບລັອກໄຟລ໌ (File Screening)

ໂຈດ: ຕັ້ງກົດຫ້າມເຊບໄຟລ໌ປະເພດ Audio/Video (Block Audio and Video Files).

ຄລິກທີ່ໄຟລ໌ດ້ານເທິງເພື່ອທົດລອງ Upload ໄປຫາ Server

👻3. ຊ່ອນໂຟນເດີ (ABE)

Access-Based Enumeration: ຫາກພະນັກງານບໍ່ມີສິດ, ໂຟນເດີຈະຫາຍໄປ ບໍ່ແມ່ນເຫັນແຕ່ເຂົ້າບໍ່ໄດ້.
